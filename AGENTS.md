# Repository instructions

## Priority: reports must stay synchronized

- Notebooks are the source of truth for reports. HTML must be exported from
  freshly executed `.ipynb` outputs whenever possible. Do not maintain a
  separate Python-to-HTML reporting pipeline or manually edit generated HTML.
- After changing a backend, report helper, source inventory, or notebook,
  execute the affected notebooks and regenerate their HTML before finishing.
  For shared backend changes, rebuild all reports:
  `uv run python examples/regenerate_reports.py`.
- Run `uv run python examples/regenerate_reports.py --check` afterward.
  A stale report, failed cell, or outdated dependency list is unfinished work;
  fix it and rebuild. Do not merely list stale artifacts in the final answer.
- HTML must visibly name its source notebook and say it was exported from
  executed outputs. Preserve build provenance so freshness can be checked.
- Maintain dependency/recovery status in one source and derive report lists
  from it. Recovered files must not remain in lists labelled missing.
- Shared Python calculation and rendering helpers are encouraged. They are
  called by notebooks; they must not independently publish competing reports.
  Standalone viewer files may be generated by a notebook as companion assets.
- If required data or execution is unavailable, state the actual blocker;
  never present old outputs as newly regenerated results.
